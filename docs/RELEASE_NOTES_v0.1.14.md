# BailingHub v0.1.14：流式对话阶段性进度提示

`v0.1.14` 改善了官方网页聊天组件在工具调用链路中的等待体验。模型已经给出简短确认语、但最终业务结果尚未返回时，组件会把这段内容作为临时进度提示保留；正式答案开始输出后，临时提示自动消失，聊天记录仍只保留最终回答。

## 用户可见结果

- 模型在调用工具前给出的简短确认语不再闪现后立即消失，而会临时显示为进度气泡。
- 工具调用、模型整理、重试和回退阶段会显示明确的状态文案。
- 最终回答开始流式输出时，进度气泡立即移除，不会留下两条助手消息。
- 任务失败或仍在后台处理时，组件显示确定性状态，不伪装成已经完成的业务结果。
- 进度动画遵循系统的“减少动态效果”设置。

## 语义边界

该能力不是推理过程展示，也不会尝试保存或呈现模型的隐藏思维链。组件只展示：

- 模型已经主动输出的短暂确认语；
- BailingHub 流式链路已经公开发送的 `reset` 与 `phase` 状态；
- 正式最终回答。

阶段性文本会规范空白并限制长度。只有正式回答进入聊天历史，临时进度提示只属于当前流式会话的界面状态。

## 自定义聊天界面

官方 `web/widget/widget.js` 会自动应用新行为。没有使用官方组件的业务侧无需修改 BailingHub API，但要获得同样体验，需要按既有流式事件实现：

- `delta`：累积当前模型文本；
- `reset`：把此前短文本转为临时进度提示，并清空正式回答缓冲；
- `phase`：更新工具调用或模型整理阶段；
- `done`：移除临时提示，只持久化最终回答。

业务侧不应把阶段性提示和正式回答同时作为两条永久助手消息保存。

## 兼容性

- 无数据库迁移。
- 不修改 Client API 或流式事件协议。
- 不修改执行器协议、工具签名、审批语义、审计边界或 ACC。
- 既有自定义聊天界面保持原行为；官方组件升级后自动获得新体验。
