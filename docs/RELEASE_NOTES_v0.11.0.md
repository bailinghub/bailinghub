# Core v0.11.0 · 多渠道任务追溯与模型上下文管理

[English](RELEASE_NOTES_v0.11.0.en.md)

## 从一句回复找到对应任务

当用户说“助手回复了，订单状态却没变”，可以从「任务 → 会话」按来源和最近活动找到对应对话。列表区分客户端、网页助手、企微和渠道送达，详情标明用户与助手的消息，打开时定位到最新消息。有原授权或执行记录的会话，可在侧栏核对授权，沿关联记录查看执行过程。各渠道展示其已保存的内容，旧记录可能只有会话头。

在「调度流」按状态、创建时间和精确路由筛选，较早的失败任务也能直接查到。追溯匹配到多条记录时，可以打开一条再返回原列表。状态标签支持键盘聚焦查看原始值，未知状态按原值显示。创建任务时，字段规则可在问号帮助中查看。[对话审计](AGENT_CONVERSATION_AUDIT.md)

## 为下一次模型请求预留空间

在「用户与用量 → 模型服务」选定调用凭证和模型后，控制台按实际调用路由查询**输入与输出合计窗口**。有确切供应商规格时自动预填，管理员可按业务需要调低；切换模型或凭证后会重新查询。若显示同一路由的既有登记值，管理员可将其作为参考。缺少可靠资料时，新服务可以先停用保存，核实后再启用。[输出预算](MODEL_OUTPUT_BUDGET.md)

宿主通过已有的 `GET /usage/v1/model/models` 查找当前 `service_id` 的 `context_window_tokens`。构造请求时，系统提示、历史消息、工具定义和本次输出预算都要计入窗口。目录返回 `null` 表示尚未登记。

对已识别的 TokenHub 输入超限拒绝，完整回执可包含 `operation.response.diagnostic.code = CONTEXT_WINDOW_EXCEEDED`。若原操作的服务配置保存了窗口，诊断也可给出该修订的上限。宿主据此决定是否压缩并保存会话检查点。收到普通 HTTP 400、网络中断或缺少最终回执时，应先查原操作，避免重复执行。[模型续跑与原单查询](MODEL_CONTINUATION.md)

从 v0.10.1 升级无需新增 SQL 迁移。部署步骤与只读验收见[升级指南](UPGRADE_v0.11.0.md)。
