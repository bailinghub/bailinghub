# 下一版说明草稿：本地智能体附件空间

状态：发布准备，尚未发布。相对公开 Core 0.7.0，候选新增附件上传契约，并包含已验收的能力发现反馈改进；正式版本与配套安装命令在发布检查时冻结。

本地智能体生成了海报或图表，后续系统却需要一个图片地址，用户往往只能手动下载再上传。本次新增会话附件空间：登记当前会话的图片，上传到部署方配置的存储，取得地址，再交给已有业务工具使用。

## 更新了什么

- **新增附件空间，首期支持图片。** PNG、JPEG、WebP，单张最高6 MiB；配套DSH每批1–8张。明确目标授权、逐项结果、成功地址复用和原上传恢复。
- **复用部署方存储。** 普通COS、OSS或显式本地存储，由管理员选择并管理文件保留；工作空间默认关闭上传。
- **改进能力发现反馈。** 区分查询匹配结果、实际返回结果与当前已加载工具；未知总数保持未知，说明工具替换和原执行关联。

例如，生成一张活动海报后设为内容封面；保存PNG经营图表供运营页面使用；或者生成商品展示图，再把URL传给商城图片更新工具。这些业务接口由各自系统提供，图片生成器由客户端选用。

## 谁需要升级

| 角色 | 本期动作 |
| --- | --- |
| 中枢管理员 | 升级Core、执行未应用迁移（新增060）、配置存储与workspace上传开关 |
| 客户端宿主开发者 | 升级匹配SDK/DSH，连接获准图片来源和持久恢复记录 |
| 业务后端开发者 | 已接收图片URL的接口可沿用；如需素材ID或转存，使用自己的素材导入接口 |
| 插件使用者 | 使用已接入附件来源的宿主；只安装通用MCP包不会自动获得电脑文件权限 |

## 如何确认生效

在已选授权的会话生成一张公开用途图片，确认目录出现附件、上传返回ready及URL；再次恢复上传仍使用原记录。再通过已接入的业务工具使用这个URL，单独查看业务成功、审批或失败结果。

## 当前边界

首期上传公开图片，不承诺文档、视频或完整文件管理。上传完成后直接使用URL，无需反复问地址。

已知业务限流窗口折算和原调用参数恢复问题另外跟踪，尚未修复；它们不代表上传失败，也不能从上传成功推导批量业务任务全部完成。正式发行前披露实际限制，不能在文案中写成已修复。
