# 控制台界面约定

- “任务”是唯一独立的顶级工作入口。用户与用量、成本观测归入“运营管理”，与各接入入口分离；用量接入设置沿用“用户与用量”的导航选中状态。低频分组默认收起，访问时展开并保留用户选择。
- 列表页面使用 `el-card shadow="never"` 作为外层容器，标题与页面操作放在 `#header`，沿用全局背景、边框与内边距。
- 页签专属操作放在页签栏右侧，随当前页签切换，不另占一行工具栏。使用 `console-page-tabs` 与 `console-page-tabs-actions` 共用布局；窄屏空间不足时再换行。
- 常规配置使用右侧抽屉；字段较多的套餐编辑可使用完整页面。主页面原则上只保留标题旁的一个问号，按当前页签集中呈现相关说明，不在列表上方重复摆放解释性标题或文案。独立抽屉内按需提供上下文帮助；错误、凭证提醒与关键操作后果保持直接可见。问号使用统一的 `QuestionFilled` 图标。
- 表格列宽由 `src/table-widths.ts` 统一管理，页面不另做拖动处理。拖动结束、读取已保存列宽及容器尺寸变化时，都将列宽收敛到当前容器；不通过隐藏滚动条掩盖溢出或裁掉内容。
- 最后一列操作使用明确宽度、`align="right"`，可设置 `column-key="actions"`；统一规则也识别标题为“操作”的无数据字段列及既有无标题操作列，并固定到右侧。固定列的过大历史宽度同样受容器约束。
- 包含表格的 Grid 容器使用 `grid-template-columns: minmax(0, 1fr)`，Flex/Grid 子项按需设置 `min-width: 0`，避免内容反向撑大容器、使列宽收敛失效。
- 窄列中的长文本使用换行或省略提示，不以增加整个表格宽度换取单行展示。

## 用量配置删除

- 套餐、身份来源、账户的删除均先打开右侧占用预览，再提交带 `request_key` 与 `expected_revision` 的原请求；提交结果不明时沿用原请求核对，不能另建删除请求。
- 未开通过的套餐、未使用的身份来源与闲置组织账户可以删除。已有额度、登录身份、请求或其他历史关联时显示具体阻断原因，沿用停用；个人账户保留与原登录身份的绑定。
- 组织成员使用账户详情内的“移除”，保留原成员关联与历史记录。删除与移除均不清理历史用量。
- 删除接口在事务内重新检查占用，前端预览不替代后端校验。已删除标识不可复用，不通过恢复或更新重新创建。
